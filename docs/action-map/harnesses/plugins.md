# Plugins and the official specs

How each harness packages skills into plugins, read from the vendor pages on 2026-09-17, and the two cross-harness specs the app validates against. Every fact carries its URL in sources.md. "Open" means the page does not say.

## The two specs

| Spec                                                                                           | What it fixes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | What the app does with it                                                                                                                                                                                       |
| ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Agent Skills, https://agentskills.io/specification                                             | A skill is a folder with `SKILL.md` (frontmatter `name`, `description` required; optional `license`, `compatibility`, `metadata`, `allowed-tools`) plus optional `scripts/`, `references/`, `assets/`. Three stages: discovery reads name and description, activation loads the body, execution reads bundled files. Validator: `skills-ref validate`. Originally Anthropic's format, now an open standard; the adopter list on the home page includes Claude Code, Codex and ChatGPT, OpenCode, pi, Cursor, VS Code, Copilot, Gemini CLI, Goose | The Fix job (U8) checks the name rule and the required fields against this page and nothing else. `spec_violations` in the scan comes from it                                                                   |
| Agent Plugins, https://agent-plugins.org and https://vercel.com/blog/introducing-agent-plugins | A plugin is a folder with `plugin.json` and fixed places for its parts: `skills/` (each a spec-shaped skill), `mcp.json`, and reverse-domain extension folders such as `com.example.client/` for client-specific data. Only skills and MCP servers are portable; commands, hooks, and agents stay client-specific. Started by Vercel; steering committee AWS, Cursor, Microsoft, OpenAI, Vercel; launch adopters ChatGPT, Codex, Cursor, GitHub Copilot, Kiro, VS Code. Schemas in the spec repo under `/schemas`                                | The app reads `plugin.json` to name a plugin and enumerates its `skills/` folder. It never writes a manifest. The marketplace format and the discovery procedure are on `/specification`, not fetched yet; Open |

The skills CLI, `npx skills`, installs skills only. It reads skills out of a `.claude-plugin/marketplace.json` or `.claude-plugin/plugin.json` when one exists, but it does not install, enable, or remove plugins. Plugin lifecycle is the harness's own tool in every case below.

## What the core must handle

- Enumerate: Claude Code cache by marketplace, plugin, version; Codex cache blind until the layout is confirmed; OpenCode plugin folders as code with no skill list; pi package roots by the `pi.skills` globs. Each enumerated skill carries `provenance = plugin` and the plugin id, so Outdated (U4) compares the cache version with the marketplace, never the tree hash.
- Switch: Claude Code through `claude plugin enable|disable`, which edits `enabledPlugins`; the app never edits that key by hand while Claude Code may run. Codex and OpenCode have no documented per-plugin switch the app can drive; the app shows the plugin and says where to switch it. pi through `pi config` only; the app does not write pi's settings for plugins.
- Never install or remove a plugin itself. Install (U5) offers the harness's own command and runs it through the user's shell, the same way it runs `npx skills`.
- Validate against the two specs only: the Agent Skills rules for `SKILL.md`, the Agent Plugins manifest rules for `plugin.json`. The Claude and Codex manifests are supersets of the same shape; the app reads the common fields.

## Open

- Codex: a vendor docs page for `/plugins`, the cache layout, and enable or disable state.
- OpenCode v2: whether a plugin can register skills, and where installed npm and git plugin packages are cached on disk.
- Agent Plugins: the `/specification` and `/schemas` pages for the marketplace format and the discovery procedure.
