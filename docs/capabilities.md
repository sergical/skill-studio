# What Skill Studio needs from your Mac

This is how Skill Studio 0.4.1 behaves. Each requirement applies to the task in its row. For example, you can scan local skills without Node or a GitHub account. “On PATH” means the program must be visible to the process that starts it. The desktop app looks in your login shell and common install locations for most tools, and asks the login shell separately for `gh`. The CLI and MCP server use the environment they are started with. [Desktop tool lookup](../crates/skill-studio-host/src/tools.rs#L347), [desktop GitHub CLI lookup](../apps/desktop/src-tauri/src/skills/skill_update_check.rs#L883), [CLI and MCP tool lookup](../crates/skill-studio-host/src/builder.rs#L35).

## macOS open-file limit

A Finder-launched app can inherit a soft limit of 256 open files. On the Mac where 0.4.1 was checked, `launchctl limit maxfiles` printed `256 unlimited`. With 438 skills, the shipped app logged six “Too many open files” errors in `~/Library/Application Support/com.skillstudio.app/timing.jsonl` across Model listing, Sessions and Packs. A separate fix is in progress. [Desktop command timing log](../apps/desktop/src-tauri/src/timing_log.rs), [machine requirements issue](https://github.com/sergical/skill-studio/issues/760).

## Gaps

1. First run detects agents and asks about telemetry. Users can reach install, packs, and updates without a check that Node and `npx` actually run, Git works, or `gh` is signed in and can reach GitHub. The desktop checks for `gh` separately from its usual tool lookup, so seeing it in a terminal is not always enough. [First-run screen](../apps/desktop/src/components/FirstRun/FirstRunScreen.tsx#L85), [Node preflight](../crates/skill-studio-core/src/install_tools.rs#L26), [GitHub CLI lookup](../apps/desktop/src-tauri/src/skills/skill_update_check.rs#L883).
2. The background skill-update status gives a generic message when `gh` is missing. Fork and GitHub Copy say “Run Check now first,” which leaves the real dependency unstated. Cached badges can outlive a working check. [Home status](../apps/desktop/src/components/Home/useUpdateCheck.ts#L47), [Copy lookup](../apps/desktop/src-tauri/src/skills/skill_install.rs#L637), [cached badges](../apps/desktop/src-tauri/src/skills/skill_update_check.rs#L1500).
3. The Finder launch can exhaust open files with an ordinary large collection. The app has no startup check for that limit, and individual watch failures only appear in logs. [Refresh startup](../apps/desktop/src-tauri/src/skills/skill_refresh.rs#L1350), [watch errors](../apps/desktop/src-tauri/src/skills/skill_refresh.rs#L1824).
4. The npm launcher tells users to reinstall globally if the matching binary is missing. A client configured to use `npx` can still reuse the broken cached entry and show only a failed connection. [Launcher error](../packages/npm/skill-studio/bin/skill-studio.js#L13), [release startup failure](https://github.com/sergical/skill-studio/issues/759).
5. Empty sessions, missing plugin comparisons, and missing Store counts can look like a feature has nothing to report. The empty views do not always say whether a local file, a supported source, or network access is missing. [Sessions empty view](../apps/desktop/src/components/Sessions/SessionsView.tsx#L321), [plugin cache](../apps/desktop/src-tauri/src/skills/skill_plugin_update.rs#L298), [Store counts](../apps/desktop/src-tauri/src/skills/skill_install_counts.rs#L400).
