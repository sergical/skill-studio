# State machines

This file lists the state machines in Skill Studio: where each one lives, its
states and legal moves, and the test that guards it. Read it before you change
a status field, a phase enum, or a busy flag.

## Rules

1. **One owner per machine.** One function decides the next state. Callers ask
   it; they do not set the field.
2. **Name every legal move.** Write the moves as a `match` (Rust) or a
   discriminated union (TypeScript). An illegal move returns an error, not a
   silent overwrite.
3. **Test the whole table.** A machine test walks every `(from, to)` pair, or
   every input row, and names the illegal move in its failure message.
4. **Derive, do not mirror.** If a state follows from other state, compute it.
   Do not store a second flag that can drift from the first.
5. **Keep the wire stable.** Serialized names (`kebab-case` phases, SQL status
   strings) do not change. New states are additive.

Cross-volume Park and Turn on record each copy in `quarantines[]` before
creating or renaming it. `stage_before_create` records a dot-prefixed sibling
on the destination volume. Copy, byte verification and full sync complete there
before one rename publishes the folder. A failed copy leaves the live destination
absent and keeps the stage. `retain_before_rename` records the source backup
before quarantine. Neither stage nor quarantine is swept as trash.

Recovery changes Pending to Interrupted and reports existing retained paths.
Failed moves with retained copies also have notices. The event payload keeps
the path and file byte count at copy time. Open writers can change the count.
Park and Turn on results include retained copies; Activity shows their paths
and sizes. No retention policy or automatic deletion is defined.

A recovery notice has two states: unacknowledged and acknowledged. Delivery to
a sink, stdout, or an MCP transport does not acknowledge it. Repeated recovery
passes return the unacknowledged records, even after their events are Interrupted.
The desktop shows a persistent toast at startup and after move commands. Its
Acknowledge action durably sets
`recovery_acknowledged` on those event payloads. CLI warns on stderr and includes
the report in JSON; MCP includes it in the tool result. These transports keep the
notice available for acknowledgement in the desktop.

Guards include
`turn_on_retains_hidden_stage_on_copy_failure_or_exposes_incomplete_live_skill`,
`turn_on_reports_stage_after_crash_before_publish_or_exposes_partial_skill`,
`cross_volume_park_reports_quarantine_after_interruption_or_hides_latest_bytes`,
`cli_park_reports_recovery_on_stderr_and_json_after_restart_or_drops_backup_notice`,
and `mcp_park_reports_recovery_in_tool_result_after_restart_or_drops_backup_notice`.
